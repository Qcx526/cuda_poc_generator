# nvlddmkm.sys 静态侦察（第一遍）

| 项 | 值 |
|---|---|
| 文件 | `C:/Windows/System32/DriverStore/FileRepository/nv_dispi.inf_amd64_c8bc842500fab35b/nvlddmkm.sys` |
| 大小 | 114.7 MB（内嵌各架构固件） |
| 映像基址 | `0x140000000` |
| 节数 | 32 |
| `.text` | RVA `0x1000`, size `0xd2e1f5` (~13.2 MB) |

## 关键导入的调用点

| 导入 | IAT 槽 | 调用点数 | 调用点 VA |
|---|---|---|---|
| `ProbeForWrite` | `0x140e071c8` | **1** | `0x1400dd4c8` |
| `ExAllocatePoolWithTag` | `0x140e077e0` | **1** | `0x1400dbc27` |
| `memcpy` / `memmove` / `memset` | — | 0（未导入，自己实现） | — |

**每个导入只有一个调用点**，说明驱动把它们封在自己的包装函数里，全驱动都走包装。

## 意义

驱动里所有"分配内核内存""校验用户指针"的动作，都汇聚到这两个地址。
从它们出发可以：

1. 反汇编这两处，识别包装函数入口
2. 找所有调用包装的地方（`E8` 相对调用）
3. 按"调用者是否处理用户输入"排序
4. 交给 LLM 判断哪个 handler 最可能越界

这比盲扫有效得多：2400 次动态探测没碰到任何东西，而静态能直接指向"钱在哪里"。

## 已知边界

- 没有符号表，函数边界要靠 `.pdata`（异常目录）恢复
- 13.2 MB 代码，全量反汇编很慢，应只反汇编候选区域
- 驱动用自己实现的 memcpy，无法靠导入表找拷贝点
