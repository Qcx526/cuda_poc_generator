# P4-X 阶段总结与下一步计划

报告语言：`zh-CN`。时间：2026-10-23。所有数字来自本仓库实测。

---

## 一、先回答那个问题

**驱动类难，不是因为技术壁垒，而是因为信息不完备。**

把现有驱动类 CVE 按"外部信息完备度"分三档：

| 档位 | 外部信息 | 能否做出 PoC | 我们的实例 |
|---|---|---|---|
| A | 有逐指令技术报告（函数、偏移、机制） | **能定位，但还需构造** | CVE-2024-0107（Talos 报告） |
| B | 只有一句公告（CWE + "执行一次驱动 API"） | **无法定位** | CVE-2024-0091 |
| C | 有公开 PoC 或测试用例 | 可直接复现 | 本批驱动 CVE 中**没有** |

结论：**B 档在给定信息下不可判定**——2166 个接口里盲试，每次崩溃都要先排除"是不是我调错了"。
0107 属于 A 档，我们把它推到了"调用点已定位、触发条件已读出"，但还差最后一步。

### 2.2 实测数据

**工具链类（主线）**

- 15 个 CVE 中 **9 个至少一次 `SUPPORTED`**
- 三组（A/B/C）× 3 CVE × 3 次 = 27 次运行：**18/27 = 67%**，95%CI [48%, 81%]
- 单次成功率方差极大：同一 CVE 可 3/3 也可 1/3 → `success@k` 是唯一可信口径

**驱动类（副线）**

- CVE-2024-0107：全流程可达（D3D9 设备/着色器/编译器），**0 次成功**
- CVE-2024-0091：接口面完整枚举，**0 次判定**

### 2.3 方法沉淀（与 CVE 无关）

1. **崩溃先归因**：47 个"崩溃"全是 d3d9 校验器的，不是驱动的。不归因就会误报。
2. **偏移要看相对谁**：`symbol+0x…` 相对符号而非模块；按错地址下断时，"没命中"本身不可信。要用机器码搜索交叉验证。
3. **判据要防回显**：用"输出含某字符串"判定命中，会匹配调试器回显命令那一行——必须匹配 `Breakpoint N hit`。这一条曾让我们连续产生 4 个假阳性。
4. **观测点要对**：程序会被运行时拷贝，盯调用方缓冲区永远看不到解码器。

### 2.4 驱动类的两个案例结论

**CVE-2024-0107（A 档，有报告）**

| 事实 | 值 | 验证方式 |
|---|---|---|
| 越界读助手 | `nvgpucomp64+0x12A3560` | 报告机器码全模块搜索，唯一命中 |
| 漏洞调用点 | `0x1503177` | 反汇编与报告逐条对齐 |
| 分派条件 | opcode 0x7D + 寄存器类别 1 + 低 24 位 < 3 | 反汇编读出 |
| 合法 SM3 能否到达 | **否**（29 条指令 + 200 例变异全否） | 断点判据 |

结论：需要"能过 D3D9 校验、但被驱动解码成 0x7D"的字节 → 这是**解析器差异**问题，不是参数区间问题。

**CVE-2024-0091（B 档，只有公告）**

| 事实 | 值 |
|---|---|
| 本机受影响 | ✅ 551.61 ∈ [550, 552.55)（原输入写 617.42 是错的，已修 36 个文件） |
| NVAPI 接口面 | ✅ 2166 个 id（静态枚举） |
| 函数名 / 原型 | ✅ 492 / 487（423 个带指针） |
| 基线调用 60 个 | 1 成功、38 错误码、12 崩溃（**均为调用方违约**） |
| 公开 PoC | 无 |

## 三、差距分析

| 差距 | 影响 | 可解性 |

## 四、下一步计划

### 4.1 主线（建议投入 80%）：把工具链的成功率做成可信数字

| 序 | 任务 | 产出 | 验收 |
|---|---|---|---|
| M1 | 7 个工具链 CVE × 5 次重复（含 P1 扩样 4 个） | `success@5` 表 + CI | 每组 ≥35 次运行 |

| M3 | `--iterations 1` vs 完整闭环 | 量化反馈迭代贡献 | 同上 |
| M4 | 终版证据包生成器 | 论文附录可直接用 | 一键出表 |

### 4.2 副线（建议投入 20%）：驱动类保持"可接续"状态

| 序 | 任务 | 触发条件 |
|---|---|---|
| D1 | 把 0107 的逆向地图整理成可交接文档 | 已完成（`P4_V_DRIVER_RE_MAP.md`） |
| D2 | 准备 VM（Hyper-V + 快照） | 要动内核类时才做 |
| D3 | 跟踪新的驱动 CVE 技术报告 | 出现 A 档信息时立即接上 |

**停止条件**（避免继续消耗）：
- 目标仍是 B 档信息（只有一句公告）→ 不投入；
- 无法获得 A 档报告或甲方资料 → 驱动类只做方法沉淀，不做成功率承诺。

### 4.3 不建议做的事

- ❌ 继续对 2166 个 NVAPI 接口盲试（崩溃不可解释）
- ❌ 在本机跑内核类（一次蓝屏可能进启动循环）
- ❌ 用"观察到的崩溃"当结论而不做模块归因

## 五、一句话总结

**框架已经能自动跑、能出数据、能自我纠错；工具链类有 67% 的可信成功率；驱动类受限于公开信息完备度，做到"定位"就停了，再往下需要报告或逆向预算。**

这不是失败，是**把不可控的部分明确标了出来**——论文里这部分本身就是有价值的分析：告诉别人"驱动类漏洞复现的瓶颈在信息，而不在生成能力"。
