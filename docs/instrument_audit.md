# 判定仪表审计：SUPPORTED 到底有多可信

报告语言：`zh-CN`。本文回答一个问题：**"SUPPORTED" 会不会把无关崩溃算成复现成功。**

现在 `SUPPORTED` 是论文唯一没被挑战的贡献，所以它自身的误判率必须能被量化。

## 1. 判定的原始规则

```
SUPPORTED ⇔ 受控样本 ≥1 个崩溃 ∧ 良性基线 0 个崩溃 ∧ 目标版本在区间内
            ∧ 机制对照 未"全部"崩溃
```

注意最后一行的**旧写法**：只要不是**全部**对照都崩，仍判 SUPPORTED，只在理由里加一句提示。

## 2. 实测：良性基线会不会自己崩

在容器里（同硬化参数）把良性 cubin 送进 `cuobjdump --dump-elf` 连跑 20 次：

```
NULLRATE ok=20 bad=0
```

即空假设崩溃率 **q = 0/20**，95% 置信上界约 **14%**。

结论：良性侧不是偶发抖动的来源。判定的薄弱点不在"基线会崩"，而在"对照崩了还算成功"。

## 3. 发现的缺陷：一条自相矛盾的 SUPPORTED

全仓库 36 条 SUPPORTED 中，有 **1 条**的理由里写着：

> 机制对照 2/3 个同样崩溃……**该崩溃不独属于恶意载荷，单一变量的隔离结论未成立**

也就是说：**我们自己的报告承认崩溃不可归因，却仍然记为成功。**
这正是审稿人会逐条读理由时抓到的东西。

## 4. 修复：任何一个对照崩了都不算成功

规则改为：

```
if control and control_crashes > 0  →  UNKNOWN（不可归因）
```

理由：单变量对照的作用就是"只改一个变量，看是否仍崩"。只要有一个对照也崩了，
就说明这次崩溃没有和受控变量绑定——**是"没隔离"，不是"隔离成立但有保留"**。

## 5. 影响面

| 批次 | SUPPORTED | 其中对照崩（修复后作废） |
|---|---|---|
| s5d（预算 2） | 2 | 0 |
| s5_it1（预算 1） | 6 | 0 |
| s5_blind（盲重试） | 9 | 0 |
| skB | 3 | 0 |
| skC | 1 | **1**（CVE-2025-23338） |

**当前主力数字（9/10、6/10、9/10）不受影响**；36 条里作废 1 条。
那条属于早期 C 组，改口径后 C 组需相应下调 1 次成功。

## 6. 论文里可以怎么写

> `SUPPORTED` 要求受控样本崩溃、良性基线不崩、且**全部**单变量对照不崩。
> 良性基线的空假设崩溃率实测为 0/20（95% 上界 14%），因此在当前样本量下，
> "基线偶发崩溃导致误判"不是主要风险；把对照也纳入硬性条件后，
> 误判需要同时满足"受控崩 + 基线不崩 + 所有对照都不崩"，三者独立失败的概率相乘。

## 7. 遗留

- 空假设率只测了 cuobjdump + 良性 cubin 一种组合，nvdisasm 路径未测；
- 对照是否覆盖了"真正的单变量"，取决于候选自己的命名与构造，无法在判定层强制；
- 若要更强的结论，应引入"随机变异对照"（随机改同样的字节，看崩不崩），
  这比"恢复基线值"更接近零假设。
