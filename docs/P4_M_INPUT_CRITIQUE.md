# P4-M 七维输入的优缺点评估与改进方向

报告语言：`zh-CN`。评估依据：23 个真实输入、15 个工具链 CVE 的批跑结果、
以及 `src/input_sufficiency.py` 的量化打分。

## 1. 先立标准

一份输入好不好，看四条：**可读**（人能审）、**可执行**（能指导变异）、
**可验证**（能判定对错）、**可演化**（跑完能变好）。
七维输入在第 1 条上很强，第 2、3、4 条基本没有。

## 2. 优点（三条，都是真的）

**A1 覆盖完整，是标准的威胁情报骨架。**
环境 → 组件 → 攻击面 → 类型 → 影响 → 根因，这条链与 CVE/NVD 的叙述结构一致，
人读起来顺，写报告时几乎可以直接引用。

**A2 分层清晰，支持增量补数据。**
我们只把 23339 的第 7 层补到"有伪代码 + 函数地址"，它就从 40% 里的一员变成
唯一一轮收敛的样本。**单层增量能带来质变**，这是分层设计最大的好处。

**A3 与下游天然对齐。**
第 5、6 层直接支撑 CVSS 与影响叙述；第 3、4 层直接进生成提示词。
不需要额外转换层。

## 3. 缺点（六条，按严重度排）

### D1 描述性 ≠ 可执行（最致命）

第 3 层写"nvdisasm 中解析 ELF 文件结构的代码"，人能懂，但**代码无法据此变异**。
缺的是：改哪个字段、偏移多少、这个字段有没有边界检查。

数据支撑：4 个 `NO_EFFECT` 全部止步于此；唯一 17/17 的 23339 恰好有
`vulnerable_code_summary`（解析循环伪代码）。

### D2 七层之间没有任何链接（实测）

7 个文件除了 `cve_id` 没有共享字段，第 7 层也不引用第 3/4 层。
后果：无法做**跨层一致性检查**——比如"攻击面说远程触发，根因却是本地文件解析"
这种矛盾，现在没人发现，模型只能自己消化。

### D3 没有置信度与来源分离

advisory 抄来的、逆向确认的、执行验证过的，三者混在同一个字符串里。
模型无法区分"这是事实"还是"这是传言"，而这两种情况下正确的策略完全不同。

### D4 没有"未知"的语义

`"N/A"`、字段缺失、空字符串、`"—"` 四种写法，语义上都是"不知道"，但程序分不清。
充分性打分只能靠字符串黑名单猜（我们就是这么做的）。

### D5 结构不稳定

同一层存在两种形状：`{"affected_component": {...}}` 与直接平铺（实测 23340 是后者）。
模型读文本不受影响，但任何按固定键取值的代码会静默拿到空。

### D6 静态，跑完不回写

同一个 CVE 第二次跑，仍然从零开始。0107 那条"ps_5_0 里没有 D3DSIO_SINCOS"
是我们用逆向换来的**负知识**，现在只存在于对话和文档里，没有回到输入。

## 4. 根因：它是档案，不是契约

档案回答"这个漏洞是什么"，契约回答"这个解析器吃什么字节、怎么算打中"。
PoC 生成需要的是后者。现在的七层是给人看的档案，被硬塞进生成流程。

## 5. 改进：三层模型 + 一个回写环

```text
Descriptive（现有 7 层，保留）
    ↓ 提炼
Operational（新增：可执行锚点）
    ↓ 标注
Epistemic（新增：置信度/来源/验证状态）
    ↓ 运行
Write-back（新增：结果回写，形成闭环）
```

### Operational 层（补 D1、D2）

| 位置 | 字段 | 作用 |
|---|---|---|
| `7.parser_model` | `entry_function{name,rva}`、`loop_pseudocode`、`consumed_fields[{name,offset,size,bound_check}]` | 变异目标 + 边界条件 |
| `3.executable_anchor` | `binary`、`input_format{magic}`、`baseline_recipe`、`affected_versions{min,max,fixed_in}` | 基线构造 + 版本门 |
| `4.invocation` / `observable_signal` | 命令行模板、成功判据（信号/退出码/模式） | 执行与评级 |

其中 `consumed_fields` 是全套里最关键的一个字段：它同时解决了"改哪里"和"为什么这里不安全"。

### Epistemic 层（补 D3、D4）

每个断言加三元组：`{value, source, verified_by}`，其中 `verified_by ∈
{advisory, reverse_engineering, execution}`，缺失即 `unknown`（显式建模，不再用 N/A 表示）。

### Write-back 环（补 D6）

每次运行后回写四类事实：实际崩溃信号、命中/未命中的字段、
被证伪的假设（负知识）、有效的最小输入尺寸。
下次同一 CVE（或同族工具）直接复用。

## 6. 三个可写进论文的创新点

### I1 输入即约束：从"描述漏洞"到"声明触发条件"

把根因层变成**可判定的 oracle**（字段/偏移/期望值/边界检查有无），
生成阶段必须先声明、运行时必须回读验证（`[CPG_ORACLE]`）。
新意不在字段本身，而在**把它变成可自动检查的契约**，从而把"模型是否理解"变成可观测量。

### I2 置信度驱动的策略选择（最有新意）

现有工作（CyberGym、DIG）对所有样本用同一套流程。我们的观察是：
**输入质量决定了应该用哪种策略**。

```text
operational 覆盖率 ≥ 60%  → 直接变异（MUTATE_DIRECT）
descriptive 覆盖 ≥ 40%    → 先探测再变异（PROBE_THEN_MUTATE）
否则                      → 先做逆向侦察（RECON_FIRST）
```

这条把"输入"和"策略"连起来，是可度量、可消融的贡献点：
同一批 CVE，固定策略 vs 置信度路由，比较成功率与成本。

### I3 输入是活的：跨 CVE 的负知识迁移

0107 的教训（ps_5_0 无 SINCOS）对同类着色器编译器漏洞都成立。
把"被证伪的假设"结构化存下来，下次直接排除，能显著减少无效迭代。
这是从"每次重来"到"越跑越快"的转变，也是论文里最容易讲清楚的价值。

## 7. 怎么验证（实验设计）

| 组 | 输入 | 预期 |
|---|---|---|
| B0 | 现有 7 层 | 基线：6/15（已有） |
| B1 | 7 层 + Operational | 主假设：`NO_EFFECT` 显著下降 |
| B2 | B1 + Epistemic 路由 | 次要假设：收敛轮数下降、成本下降 |

指标：`SUPPORTED` 率、平均收敛轮数、假阳性率（人工抽检）、每 CVE token 成本。
消融：去掉 `consumed_fields`、去掉 oracle 声明、去掉负知识，各看掉多少。

## 8. 迁移路线（不推翻现有数据）

1. Operational 层全部为**可选块**，缺了不影响现有流程（向后兼容）；
2. 先给 3 个 CVE 手工补全（23339 已有大半），验证 B1 假设；
3. 补全手段自动化：版本区间从 NVD 抽、入口函数从二进制抽（我们有 RE 能力）、
   基线配方从工具文档抽；
4. 结构统一（D5）单独做一次数据迁移，加校验器防止再分裂。

## 9. 一句话结论

七维输入**作为档案是合格的，作为契约是不合格的**。
改进的重心不是再加几层描述，而是补上"可执行锚点"与"置信度"，
让输入从"给人看的说明"变成"给流程用的约束"。
