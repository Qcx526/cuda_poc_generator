# P4-T 样本扩展：还该测哪些类型的漏洞

报告语言：`zh-CN`。回答"要不要再找不同类型的漏洞"——**要，而且这是当前最大的效度风险。**

## 1. 现状：三个效度威胁

现有 23 个输入、实测成功 9 个，但真正进入 A/B/C 消融的只有 3 个，且：

| 维度 | 现状 | 威胁 |
|---|---|---|
| 组件类型 | 全部是 CUDA 命令行工具（cuobjdump / nvdisasm） | 结论可能只对"文件解析器"成立 |
| CWE | 集中在 125/131/476（越界读、尺寸算错、空指针） | 对其他缺陷类别（UAF、竞态、命令注入、DLL 劫持）无证据 |
| 平台/媒介 | 全部 Linux 容器 + 文件输入 | 对 API 序列、IOCTL、报文类目标无证据 |

CWE 分布（23 个样本）：CWE-476 ×4、CWE-125 ×3、CWE-190 ×2、CWE-787 ×2，
其余 12 类各 1 个。**样本天然向"内存安全 + 文件解析"倾斜**，因为那正是我们最容易跑通的类别。

## 2. 抽样原则（先定原则，再挑样本）

1. **按 CWE 分层，而不是按"能不能跑"挑。** 只选跑得动的样本 = 选择性偏差，
   评审一眼能看出来；
2. **每格至少 3 个样本**才能谈"这类能做/不能做"；
3. **跑不动的也要报。** 报告 `NEEDS_BACKEND` 是结果（能力边界），不是失败；
4. **优先选有公开 PoC 或详细 advisory 的**，否则 ground truth 不清，成功与否无法判定。

## 3. 候选矩阵（按代价从低到高）

| 批次 | 类型 | 候选 | 新后端需求 | 价值 |
|---|---|---|---|---|
| **P1** | 工具链扩样 | CVE-2024-0124（UAF）、53877（空指针）、2025-23247（整数溢出）、23346（空指针） | 无 | 4 个 CVE 覆盖 CWE-416/476/190，**零成本**，最快消除"同类质疑" |
| **P2** | Windows 工具 | CVE-2025-33231（Nsight，DLL 搜索路径劫持，CWE-427） | `windows_native`（已有） | 首次覆盖**非内存破坏类**缺陷 |
| **P3** | 库类 | CVE-2025-23273（nvJPEG，CWE-369） | 容器需 `--gpus all` | 覆盖"库 + GPU 依赖"路径 |
| **P4** | 服务类 | CVE-2025-23316（Triton，CWE-78 命令注入） | packet/HTTP 媒介 + 网络 | 覆盖"输入不是文件"的形态 |
| **P5** | 内核驱动 | CVE-2026-24191（CWE-367 竞态） | VM 快照后端 | 覆盖内核 + 竞态，代价最高 |
| — | 用户态驱动 | CVE-2024-0107（CWE-125） | 已有（`--allow-native`） | 已在推进，卡在 D3D9 字节码构造 |

## 4. 为什么 P1 应该立刻做

- 不需要任何新后端，现有容器就能跑；
- 4 个新 CVE 把样本从 3 扩到 7，且 CWE 从 3 类扩到 6 类；
- 它们此前跑过：0124/53877 是 `UNCLASSIFIED`、23247 是 `NO_EFFECT`、23346 是 `INCONCLUSIVE`——
  **正好是三类不同失败**，加上新对照契约与规格后重跑，能直接看出"哪些失败是能力问题、哪些是知识问题"。

## 5. 论文里该怎么呈现

不是"我们支持 N 类漏洞"，而是**能力矩阵**：

| 类型 | 样本数 | success@k | 平均轮数 | 主要失败原因 | 后端 |
|---|---|---|---|---|---|
| 工具链-文件 | 7 | ? | ? | ? | container |
| Windows 工具 | 1–2 | ? | ? | ? | windows_native |
| 库 | 1–2 | ? | ? | GPU passthrough 缺失 | container+gpu |
| 服务 | 1 | ? | ? | packet 媒介未实现 | — |
| 内核 | 1 | — | — | `NEEDS_BACKEND` | VM 快照 |

**把"做不了"如实列出来，比只报成功的格子更有说服力。**

## 6. 结论

- **要测，但不要一次全上。** 先 P1（零成本扩样到 7 个、6 类 CWE），再 P2（非内存类），
  P3–P5 按后端建设进度推进；
- **抽样必须先分层再抽**，否则"我们只测了能测的"会成为论文最容易被攻击的点；
- 当前 C 组消融跑完后，P1 可以直接接上，不需要等驱动线。
