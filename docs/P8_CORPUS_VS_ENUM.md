# 一次性枚举 vs 队列累积：同预算对照

问题：把 fuzzing 的语料演进搬过来（保留"走得深"的样本继续变异），
能不能比现在的"每个变体都从种子改一处"更有效？

## 实验设计

| 项 | 设置 |
|---|---|
| 种子 | 12.4 能完整解析的良性 cubin（2536 字节） |
| 目标 | `cuobjdump --dump-elf`，镜像 `nvidia/cuda:12.4.1` |
| 预算 | 每组 150 次执行 |
| 变异词表 | **两组完全相同**：11 个字段 × 6 个值 + 4 个结构操作 |
| 唯一差别 | 队列组会保留"输出变多"的样本，并把它作为下一轮的父本 |
| 指标 | 独立崩溃点 / 每百次执行 |

## 结果

| 组 | 执行 | 崩溃点 | 每百次 | 被拒 | 最深输出 |
|---|---|---|---|---|---|
| flat（现状） | 150 | **2** | 1.33 | 36 | 862 KB |
| queue（累积） | 150 | **2** | 1.33 | **88** | 2.4 MB |

命中的点：

```
flat   cuobjdump+0x67000   libc.so.6+0xa5000
queue  cuobjdump+0x67000   libc.so.6+0x19d000
```

**打平。** 累积没有多找到一个点，却把拒绝率从 24% 抬到 **59%**。

## 为什么没赢：深度代理是可被欺骗的

队列的判据是"输出变多了就保留"。而这个信号会奖励**垃圾输出**：

- 把某个 `sh_size` 撑到极大 → cuobjdump 打印几十万字节的垃圾
- 这在"输出量"上表现为"走得极深"，实际上它已经在崩的边缘
- 队列把这种样本收进来当父本，在它基础上再改 → 绝大多数直接不合法

结果就是：**队列越走越偏，越偏越不合法**（59% 被拒）。

depth 从 862 KB 涨到 2.4 MB，看着像"探索更深"，其实只是在放大同一个垃圾输出。

## 这个负结果说明什么

1. **在"崩溃点"这个目标上，一次性枚举没有被击败**。同预算下产出相同。
2. **"输出量"不能当覆盖率的替代品**。它和目标（新崩溃点）弱相关，且容易被单个字段的极端值刷高。
3. 要用真覆盖率，必须插桩（DynamoRIO / Intel PT / 重编译），成本高一个数量级——而即便拿到，"新边"和"新崩溃点"的关系在解析器上也未必强。

## 什么情况下队列会赢（推测，未验证）

- 目标需要**多步累积**才能到达（例如协议状态机、需要连续三次合法交互）
- 深度信号与目标强相关（真边覆盖）
- 变异词表足够细，使"深一步"仍保持合法（我们的字段级变异太粗，一步就可能致死）

## 对我们的流程意味着什么

保持现状：**一次性枚举 + 台账 + 跨版本判定**。队列不作为默认路径。

但保留 `src/corpus_lab.py` 作为可复用的对照装置——换目标（比如将来的驱动层、或真覆盖率）时，
同一套框架可以再测一次，而不是重新造实验。
