## 工程解析：cuda_poc_generator

对工程做了完整走读（读源码 + 实际跑通 CLI），结论存档：

- 定位：NVIDIA CUDA 漏洞 PoC 自动生成 Agent（LangChain + ChromaDB RAG + OpenAI 兼容中转接口驱动）。
- 实际流水线只有 3 阶段（**单次生成版**）：情报收集 → 7 层模型漏洞分析 → PoC 代码生成。README 里写的 5 阶段迭代/人在回路（feedback_loop.py）**已不存在**，README 相对代码已过期。
- 运行环境：conda env `cuAgent`（Python 3.13.12）已装齐 langchain-chroma / chromadb / sentence-transformers / torch / tavily，`main.py --help` 可跑通。managed python 3.13.12 与 conda base 都缺 RAG 依赖。
- CLI：`python main.py --cve-id <CVE-ID>` / `--input-dir` / `--output-dir` / `--no-rag` / `--log-level`；`--cve-id` 与 `--input-dir` 互斥。
- 输入契约：`data/inputs/<CVE-ID>/` 下 7 个 JSON（D1 os_environment … D7 root_cause），文件名字段在 `config/default.yaml` 的 `vulnerability.input_files` 中定义。
- 输出契约：`data/outputs/<CVE-ID>/cuda_analysis_v1.json`（root_cause_analysis + verification_strategy）+ `cuda_poc_v1.py`。
- 已有样本 CVE：2022-21821 / 2023-0196 / 2024-0076 / 2024-0124 / 2025-23308 / 2025-23339。
- **配置与 README 不一致**：`config/default.yaml` 实际 `api_base` = `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，`model_name` = `kimi-k2.7-code`；README 仍写 niubiapi.com + gpt 系列。
- 未在 README 中记录的模块：`src/env_probe.py`（环境探测）、`src/tools/`（env/compile/elf_ops/inspect/search 可导入工具库）、`src/models/`（pydantic 模型）。

## 源码中值得注意的健壮性短板

- `core_expert.analyze()` 返回的 analysis 若缺字段只 warning，不中止。
- `code_generator._validate_code()` 的"缺失导入"检测会把 `self.xxx` 之类误判的可能存在，但当前实现只扫 `ast.Name`，误报概率较低；真正的风险是它**不能**捕获运行期错误。
- `_query_web_search` 捕获所有异常并静默返回空串，Tavily 失败时无任何提示。
